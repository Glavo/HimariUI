# ADR-003: Keep compiler plugins optional

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 4 (ADR-003), 7, and 26; M1 ordinary-Java comparison requirements.
- **Supersedes:** None
- **Superseded by:** None

## Context

Compiler instrumentation can improve ergonomics and diagnostics, but making correctness depend on it would constrain build tools, Native Image, debugging, and ordinary Java use.

## Decision

Runtime correctness and the baseline application API must work without source rewriting, bytecode rewriting, generated application code, or a compiler plugin. Optional tooling may add diagnostics, source maps, skip optimization, hot reload, or static analysis.

## Consequences

Every M1 structural candidate is evaluated through ordinary Java samples before optional tooling is applied. Annotation processing alone cannot stand in for method-body instrumentation.

## Evidence

`RUNTIME-SAMPLE-001` now checks in `runtime-decision-rubric-v1`, thirteen candidate-neutral fixtures, an auditable source-marker format, deterministic Headless execution, balanced ownership instrumentation, and a canonical report schema. Candidate source files are compiled as ordinary Java and measured without generated application code. The rubric records source lines, semantic keys, deferred getters, structural controls, group boundaries, generic noise, callback wrappers, execution counts, allocations, retained memory, phase invalidation, structured diagnostics, Native Image evidence, and any claimed reload identity.

`RUNTIME-SPIKE-GROUPED-001` consumes that contract through three measured application files using handwritten Java groups, branches, keys, bindings, and effect callbacks; its descriptor declares no application transformation. Its default standalone report remains incomplete because external evidence is intentionally supplied only by the independent decision profile.

`RUNTIME-SPIKE-ONESHOT-001` supplies the independent ordinary-Java alternative. Its three measured application files initialize owners once, defer property reads through explicit bindings, and express dynamic branches and collections with `Show` and `ForEach`; they import no grouped-runtime representation and declare no application transformation. All thirteen fixtures pass.

`RUNTIME-SPIKE-HYBRID-001` supplies the third independent ordinary-Java candidate. Stable owner initializers and property bindings remain one-shot, while only explicit small `structure(...)` declarations rerun for topology. Ordinary `if` and `for` statements declare semantic-keyed fragments rather than relying on specialized conditional or collection controllers. Its three measured application files declare no transformation and pass all thirteen fixtures.

The `m1-runtime-decision` profile regenerates name-free complete-source ceremony packets, verifies their checked review by SHA-256, runs all three real candidates in a no-fallback GraalVM 25 Native Image executable, then produces evidence-backed reports in three isolated JVM processes. Every candidate passes 13/13 fixtures without transformation or disqualification. ADR-023 selects the grouped structural model through the previously frozen score and tie-break sequence; optional compiler assistance remains an optimization only.

## Replacement

None. Optional tooling may receive its own ADR without replacing the baseline guarantee.
