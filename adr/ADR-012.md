# ADR-012: Report capability loss and fallback explicitly

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 1, 3, 4 (ADR-012), 18, and 26; PLATFORM_CONFORMANCE.yaml capability profiles.
- **Supersedes:** None
- **Superseded by:** None

## Context

Silent fallback makes input, accessibility, color, GPU, IME, and font behavior impossible to diagnose and can misrepresent semantically different output as supported.

## Decision

Capability discovery and selection return structured effective configurations, fallback reasons, and unavailable modes. The framework never silently drops input or substitutes semantically incorrect behavior.

## Consequences

Each platform and surface reports dynamic capabilities truthfully. Required profiles fail when a fallback violates their contract; optional capabilities remain disabled until their independent conformance evidence passes.

## Evidence

Platform, renderer, text, accessibility, and HDR profiles name supported modes, fallback fixtures, and evidence artifacts.

## Replacement

None.
