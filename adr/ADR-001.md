# ADR-001: Keep the core independent of `java.desktop`

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 2.1, 4 (ADR-001), and 26; M0 `verifyNoDesktopModule` gate.
- **Supersedes:** None
- **Superseded by:** None

## Context

AWT, Swing, Java2D, JavaFX, and SWT would import desktop abstractions and native deployment assumptions that conflict with HimariUI's pure-Java core and target-neutral model.

## Decision

Core modules define their own image, font, color, input, window, clipboard, and related value types and must not require `java.desktop`. Java2D may appear only in isolated tests or Oracle tooling.

## Consequences

Every core runtime graph is checked with `jdeps`. Optional AWT/Swing embedding must remain a separately allowlisted, non-default artifact and cannot influence common APIs.

## Evidence

The accepted execution summary and distribution gates in `PLANS.md` define the boundary. M0 build artifacts pass `verifyNoDesktopModule`.

## Replacement

None. A future interop artifact does not supersede this core constraint.
