# ADR-021: Contain application callback failures at declared error boundaries

- **Status:** Proposed
- **Date:** 2026-08-14
- **Decision milestone:** M1 / RUNTIME-ADR-001 and phase-failure fixtures
- **Evidence:** Required: injected failures in structure, measure, placement, paint, effects, cleanup, and native callback entry with deterministic debug/release outcomes.
- **Supersedes:** None
- **Superseded by:** None

## Context

Rerunnable application callbacks may fail after staging work. Unspecified propagation can corrupt committed trees, leak ownership, cross native callbacks, or produce nondeterministic presentation.

## Decision

The requirement is fixed but its developer-facing containment scope and retry policy are not yet accepted. Every callback kind must have a declared boundary, atomic cleanup, deterministic diagnostics and fallback, and a documented release-build policy. Failures may never escape a native callback boundary.

## Consequences

M1 runtime candidates must demonstrate recovery without partial trees, mixed epochs, leaked effects/resources, or repeated uncontrolled retries. Error-boundary APIs cannot stabilize before fixture evidence selects the scope and behavior.

## Evidence

Acceptance requires per-phase failure injection, nested-boundary behavior, transaction cleanup, fallback presentation, retry/disposal traces, and native-entry containment results.

## Replacement

This proposed record will be accepted or superseded when M1 fixes the contract from reviewed fixture evidence.
