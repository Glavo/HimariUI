# ADR-023: Use explicit grouped recomposition for structural updates

- **Status:** Accepted
- **Date:** 2026-08-15
- **Decision milestone:** RUNTIME-ADR-001
- **Evidence:** `runtime-decision-rubric-v1`; the three thirteen-fixture candidate reports; checked evidence under `evidence/m1-runtime-decision`; and `./gradlew -g .gradle-user-home :spikes:runtime-decision:conformance`.
- **Supersedes:** None
- **Superseded by:** None

## Context

ADR-015 deliberately separated fine-grained value propagation from the unresolved structural-update model. Without a compiler plugin, HimariUI had to choose among handwritten restartable groups, initialize-once owners with specialized `Show`/`ForEach` controllers, and initialize-once owners with small rerunnable structural scopes. The choice must cover ordinary-Java ergonomics, identity, failure atomicity, phase attribution, current-viewport materialization, diagnostics, Native Image, and resource lifetime rather than copying a framework whose ergonomics depend on source transformation.

All three candidates pass the frozen correctness suite and Native Image run, and none fails the blinded ceremony review. In the reviewed scoring run, explicit grouped recomposition scores 71.920199, one-shot signal ownership scores 71.388701, and fine-grained structural scopes score 68.270262. The first two are within the frozen three-point tie range. Explicit grouped recomposition therefore wins the first fixed tie-breaker with 61 accidental-ceremony markers against one-shot's 95; it also records fewer phase invalidations and lower peak retained candidate storage. This decision preserves the measured costs: grouped execution is roughly twice as slow in the reviewed isolated-process runs and allocates roughly 4.2 times as many steady-state bytes as the best signal candidate.

## Decision

Use explicit grouped recomposition for production structural updates. This selects the structural identity and restart model only; it does not replace ADR-015's fine-grained producer/consumer graph or require value-only changes to be expressed as structural reads.

The production contract is:

1. Application code declares every restartable component or structural group through ordinary Java and supplies a stable handwritten source identity. Correctness must not use stack inspection, line numbers, lambda class names, allocation order, generated source keys, change masks, restart lambdas, or compiler-inserted memoization.
2. A source read made while a structural group executes is owned by that group and may invalidate that group. A read made by a typed property binding or phase callback remains a fine-grained consumer and invalidates only its declared earliest phase and required successors. Passing an eager plain value does not manufacture a reactive dependency; changing component input must be read from a tracked source or supplied through a typed binding.
3. Unkeyed child groups and local memory use positional identity only while the handwritten source identity remains at the same unkeyed sibling position. Reorderable collections, explicit reparenting, and any sibling set whose execution order can change require application semantic keys. Duplicate keys reject the complete draft.
4. Local state, bindings, effects, cleanup, and retained resources belong to the nearest explicit group. Conditional structure declares retain-on-hide or dispose-on-hide. A hidden retained subtree keeps local memory and identity but deactivates effects and reactive consumers; removal disposes children before parents.
5. Every structural attempt builds a private draft against one stable state epoch. Mounted topology, property targets, dependency edges, ambient overrides, effect changes, and animation metadata become visible only through one `UiCommitTransaction`. Failure or cooperative cancellation discards the draft and preserves the previous committed tree and presentation targets.
6. Effects mount or update only after a successful commit. Cleanup runs deterministically child-before-parent; cleanup failures are aggregated and reported without skipping the remaining owned cleanup.
7. Ambient reads follow the same boundary: a structural read invalidates its owning group, while a typed phase read invalidates only that consumer. Subtree overrides own distinct versions, and changing an override cannot invalidate consumers shadowed by a nearer unchanged override.
8. Adopt ADR-020's explicitly scoped current-measure materialization. Only a layout container's declared materialization group may create or remove keyed descendants during measure; it uses the current constraints and viewport, remains inside the current state/UI attempt, and stages its result for atomic commit before placement.
9. Adopt ADR-021's error-boundary contract. The innermost active boundary contains an application callback failure; fallback failure escalates once to its parent. Retry requires an explicit reset or later declared recovery action and cannot loop automatically. Debug and release builds share identical atomicity, ownership, and retry semantics; they may differ only in diagnostic detail and framework-owned diagnostic presentation.
10. The first production scheduler is non-preemptive. It may expose cooperative cancellation checkpoints for bounded staged work because the selected candidate proves their cleanup, but it does not claim speculative parallel composition, preemption, or conflict retry.

## Consequences

`STRUCTURE-001` may implement group records, positional memory, semantic-keyed reconciliation, retained inactive branches, and failure-atomic drafts. The spike's storage classes are evidence, not production API, and may be replaced as long as the selected observable contract and conformance metrics remain intact.

Public application samples must expose explicit group boundaries honestly. Optional code generation may infer source identities, memoize stable callbacks, or improve diagnostics, but ordinary Java remains complete and supported. An optimization may skip a group whose tracked versions prove it clean or lower draft allocation, but it may not change identity, read-site attribution, effect order, or failure visibility.

The grouped candidate's execution and allocation outliers become explicit optimization targets for `STRUCTURE-001`, `MOUNT-001`, and `PERF-BASE-001`; they are not permission to weaken the correctness or ergonomics result. The one-shot and hybrid spikes remain checked reference implementations and API-design evidence. Their specialized control-flow or direct-binding techniques may inform internal optimizations, but introducing initialize-once structural ownership as a second public model requires a replacement ADR.

## Replacement

Replace this ADR only with new ordinary-Java application evidence and a versioned decision rubric. Reconsideration is warranted if production implementation cannot bring grouped execution and allocation within later accepted budgets, real application charters make explicit groups pervasive, a compiler-independent signal model demonstrates materially better structural semantics without specialized-controller burden, or the project accepts a mandatory compiler transformation in a separate ADR. Performance measurements alone still cannot override identity, atomicity, diagnostics, or ordinary-Java usability.
