# ADR-013: Use consistent coordinates, module names, and packages

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 1.4, 2.3, 4 (ADR-013), 6, and 26; BUILD-001 module descriptors and publications.
- **Supersedes:** None
- **Superseded by:** None

## Context

Repository layout, Maven coordinates, JPMS names, and Java packages need one predictable mapping without exposing every implementation module as a user entry point.

## Decision

Use Maven group `org.glavo.himari`, artifact IDs `himari-<area>`, and JPMS/package names `org.glavo.himari.<area>`. Present coarse entry points through `himari-bom`, `himari-desktop`, and `himari-ui`; keep fine-grained runtime, layout, graphics, renderer, text, platform, and testing artifacts composable. Publish `himari-ffi` and the Vulkan, D3D12, and Metal RHI implementations only as internal composition artifacts. Do not introduce `gui-*` names or a JNA production artifact.

The accepted mapping is:

| Artifact | JPMS module or publication role | User surface |
|---|---|---|
| `himari-bom` | version platform; no runtime module | primary dependency-management entry |
| `himari-desktop` | `org.glavo.himari.desktop` | primary desktop entry |
| `himari-ui` | `org.glavo.himari.ui` | common UI entry |
| `himari-state` | `org.glavo.himari.state` | fine-grained value reactivity |
| `himari-runtime` | `org.glavo.himari.runtime` | declarative runtime |
| `himari-layout` | `org.glavo.himari.layout` | layout primitives |
| `himari-graphics` | `org.glavo.himari.graphics` | graphics values and display lists |
| `himari-render-software` | `org.glavo.himari.render.software` | software renderer |
| `himari-render-gpu` | `org.glavo.himari.render.gpu` | backend-neutral frame compiler/RHI |
| `himari-font` | `org.glavo.himari.font` | font parsing and rasterization |
| `himari-text` | `org.glavo.himari.text` | shaping and text layout |
| `himari-controls` | `org.glavo.himari.controls` | stabilized controls |
| `himari-platform-api` | `org.glavo.himari.platform.api` | internal target-neutral platform contracts |
| `himari-platform-windows` | `org.glavo.himari.platform.windows` | Windows implementation |
| `himari-platform-macos` | `org.glavo.himari.platform.macos` | macOS implementation |
| `himari-platform-linux-wayland` | `org.glavo.himari.platform.linux.wayland` | required Linux implementation |
| `himari-platform-linux-x11` | `org.glavo.himari.platform.linux.x11` | optional compatibility implementation |
| `himari-platform-headless` | `org.glavo.himari.platform.headless` | deterministic Headless platform |
| `himari-testing` | `org.glavo.himari.testing` | application test support |
| `himari-ffi` | `org.glavo.himari.ffi` | internal generated-FFM support |
| `himari-rhi-vulkan` | `org.glavo.himari.rhi.vulkan` | internal Vulkan implementation |
| `himari-rhi-d3d12` | `org.glavo.himari.rhi.d3d12` | internal D3D12 implementation |
| `himari-rhi-metal` | `org.glavo.himari.rhi.metal` | internal Metal implementation |

The BOM manages every published coordinate above at one release version. Applications normally declare the BOM plus `himari-desktop` or `himari-ui`; platform artifacts pull their required FFM/RHI implementation dependencies without asking applications to declare `himari-ffi` or an RHI backend directly. The default desktop graph excludes X11 and contains no JNA artifact.

## Consequences

Repository directories may be shorter, but complete artifact/module/package names remain isomorphic. Optional `himari-platform-linux-x11` is never a default dependency and is not advertised stable until its separate profile passes.

## Evidence

BUILD-001 establishes `org.glavo.himari` modules and `himari-*` artifacts; future publication metadata and the BOM must preserve the mapping in PLANS.md Section 2.3.

## Replacement

None. Renaming accepted coordinates requires a superseding ADR and migration plan.
