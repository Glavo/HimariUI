# ADR-010: Use UTF-16 public indices with explicit grapheme and cluster maps

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 4 (ADR-010), 15, and 26; Unicode segmentation and shaping references in REFERENCES.lock.
- **Supersedes:** None
- **Superseded by:** None

## Context

Java strings are indexed by UTF-16 code units, while caret movement, deletion, selection, bidi, and shaping require grapheme and glyph-cluster boundaries.

## Decision

Public text ranges use Java `String` UTF-16 offsets. Text services expose explicit grapheme, bidi, line-break, and shaping-cluster maps, and shaping results preserve UTF-16 cluster start/end offsets.

## Consequences

Callers can interoperate with Java strings without confusing code units with user-perceived characters. Editing operations must route through boundary APIs rather than incrementing offsets blindly.

## Evidence

M4 and M8 corpora cover surrogate pairs, combining sequences, bidi text, ligatures, emoji sequences, and malformed boundaries against pinned Unicode/HarfBuzz Oracles.

## Replacement

None.
