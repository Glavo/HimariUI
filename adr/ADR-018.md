# ADR-018: Make animation transaction-scoped, interruptible, and phase-aware

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 4 (ADR-018), 7, 18, and 26; SwiftUI animation references in REFERENCES.lock.
- **Supersedes:** None
- **Superseded by:** None

## Context

Curve-only animation APIs do not define committed values, interruption, velocity, atomic sampling, lifecycle transitions, reduced motion, or which pipeline phases must run.

## Decision

Committed state and mounted properties are authoritative model targets; active animation derives separate presentation values. Immutable animation metadata travels with the state/publication transaction. All due presentation values sample one monotonic timestamp and publish one presentation epoch without writing application state or executing effects. Each property declares typed interpolation and earliest phase impact.

## Consequences

Compatible replacements preserve current value and meaningful velocity; other policies explicitly restart, blend, or snap. Bounded compositor animation contains no application callback and remains reproducible by the UI runtime. Structural, matched-geometry, and reduced-motion behavior use explicit identity and lifecycle contracts.

## Evidence

M1 and later profiles cover atomic sampling, retargeting, velocity, cancellation/replacement outcomes, phase invalidation, structural transitions, manual-clock replay, and reduced motion.

## Replacement

None. Surface API design may adapt SwiftUI ideas but cannot require its compiler/macro or per-frame closure model.
