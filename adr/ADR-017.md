# ADR-017: Make scene output transport-ready without making remote rendering core policy

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 3.3, 4 (ADR-017), 6, 12, and 26; SCENE-CODEC-001 requirements.
- **Supersedes:** None
- **Superseded by:** None

## Context

Deterministic replay, process isolation, browser presentation, and diagnostics need a stable boundary, but networking and remote-session policy would burden the core with unrelated security and transport concerns.

## Decision

Define canonical, versioned, bounded, pointer-free encodings for immutable scenes/display lists, resources, color/profile/presentation data, semantics snapshots, and normalized input. The encoding is independent of Java object identity, `MemorySegment`, FFM, RHI, and native handles. Core owns codecs and offline replay, not networking or session policy.

## Consequences

In-process snapshots remain the default. Future local Web and remote clients consume the same logical boundary through target-specific artifacts and cannot receive component trees, callbacks, arbitrary code, RHI commands, or native GPU commands.

## Evidence

M3 owns canonical round trips, feature negotiation, resource generations and limits, malformed-input rejection, offline replay, and decoder fuzzing.

## Replacement

None. A future transport ADR may build on but not weaken the core codec boundary.
