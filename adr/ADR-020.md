# ADR-020: Make measure-time structural materialization an explicit contract

- **Status:** Proposed
- **Date:** 2026-08-14
- **Decision milestone:** M1 / RUNTIME-ADR-001
- **Evidence:** Required: ordinary-Java grouped, one-shot, and hybrid fixtures for viewport-driven keyed materialization, phase tracking, commit/failure cleanup, scrolling anchors, and one-frame-lag alternatives.
- **Supersedes:** None
- **Superseded by:** None

## Context

Viewport-driven containers know which children should exist only after constraints and available size are known, while the normal runtime flow orders structure before measure.

## Decision

No mechanism is accepted yet. `RUNTIME-ADR-001` must choose either explicitly scoped measure-time structural materialization with defined state/phase/commit semantics or a previous-viewport scheme with a documented one-frame lag. An emergent or unrestricted subcomposition path is not permitted.

## Consequences

`LazyList`-style implementation cannot hard-code a mechanism before M1 evidence. The selected contract must preserve keyed identity, failure atomicity, phase tracking, anchor-relative/double cumulative offsets, and deterministic Headless behavior.

## Evidence

Acceptance requires the frozen M1 rubric, micro-fixtures, realistic sample port, invalidation traces, lifecycle results, and measured ergonomics/performance for each non-disqualified candidate.

## Replacement

This proposed record will be accepted or superseded by `RUNTIME-ADR-001` after the named evidence is reviewed.
