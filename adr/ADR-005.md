# ADR-005: Make the software renderer normative

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 1.4, 4 (ADR-005), 10, 22, and 26; M3 golden and differential gates.
- **Supersedes:** None
- **Superseded by:** None

## Context

GPU-first behavior is difficult to specify across APIs and vendors and cannot provide a deterministic Headless Oracle by itself.

## Decision

Each drawing operation is specified and implemented in the scalar pure-Java software renderer before a GPU backend can become the default for that operation.

## Consequences

The software renderer owns normative geometry, coverage, blending, color, codec, and golden behavior. GPU implementations may use bounded tolerances but must pass differential profiles against the reference path.

## Evidence

M3 establishes scalar golden fixtures, reproducible captures, fuzzing, and CPU/GPU eligibility criteria.

## Replacement

None. Optimized CPU paths remain subordinate to the scalar reference implementation.
