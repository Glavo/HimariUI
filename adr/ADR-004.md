# ADR-004: Track reactive reads by execution phase

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 4 (ADR-004), 5, 7, and 26; phase-isolation fixtures required by M1 and M2.
- **Supersedes:** None
- **Superseded by:** None

## Context

A generic dirty flag makes property changes rerun unrelated structure, layout, paint, semantics, and hit testing, while an eager value may erase the dependency needed for a narrow binding.

## Decision

Reactive reads are attributed to `STRUCTURE`, `MEASURE`, `PLACE`, `PAINT`, `COMPOSITE`, `SEMANTICS`, or `HIT_TEST_INDEX`. Invalidating a consumer schedules only that phase and required successors. A binding declares its earliest possible phase impact.

## Consequences

Phase consumers remain independently restartable. The runtime must preserve the read location and cannot claim property-level invalidation after application code eagerly erased the dependency. ADR-020 is the only planned exception to normal phase ordering.

## Evidence

M1/M2 fixtures must demonstrate narrow invalidation, successor propagation, and authoritative semantics/hit-test geometry for reactive and animated values.

## Replacement

None. ADR-020 may define a scoped ordering exception without superseding phase tracking.
