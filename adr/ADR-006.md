# ADR-006: Use an explicit RHI resource model

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 4 (ADR-006), 11, 22, and 26; Vulkan, D3D12, and Metal validation profiles.
- **Supersedes:** None
- **Superseded by:** None

## Context

Vulkan, D3D12, and Metal differ in synchronization details but all require explicit ownership, resource use, pass boundaries, and submission ordering.

## Decision

The backend-neutral RHI represents resource creation and lifetime, declared usage/access, pass dependencies, pipeline state, submission order, and completion explicitly. The frame compiler emits logical transitions that each backend materializes as native barriers or validation requires.

## Consequences

Higher-level Canvas and scene APIs do not expose Vulkan/D3D12 barrier objects or OpenGL-style implicit state. Backend implementations must report capability and validation differences explicitly.

## Evidence

M3 and platform GPU milestones require resource-lifetime, usage, pass-dependency, synchronization, and validation tests.

## Replacement

None.
