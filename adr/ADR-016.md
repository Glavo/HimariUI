# ADR-016: Do not lower the Java baseline for speculative targets

- **Status:** Accepted
- **Date:** 2026-08-14
- **Decision milestone:** ADR-BOOTSTRAP-001
- **Evidence:** PLANS.md Sections 1.4, 3.3, 4 (ADR-016), and 26; future A0 mobile-AOT feasibility profile.
- **Supersedes:** None
- **Superseded by:** None

## Context

Constraining common code to current ART or an unproven mobile compiler would weaken the desktop and Headless architecture before mobile feasibility exists.

## Decision

Shared implementation may use stable Java 25 language and runtime features. Android and iOS are supported only when a mobile AOT toolchain compiles representative ordinary Java 25 source unchanged, including stable memory APIs used by the core. A failing target is deferred rather than creating an older source set or replacing Java 25 features.

## Consequences

ART compatibility is not a current baseline. A full ART execution profile requires a future supplementary or replacement ADR; target host glue remains isolated from core and desktop artifacts.

## Evidence

The future A0 profile must compile and run representative core, FFM-independent subsystems and validate target packaging without source rewriting.

## Replacement

None.
